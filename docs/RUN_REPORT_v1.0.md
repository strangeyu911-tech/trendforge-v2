## 3. 失败归因分布（5 条总编否决）

否决由 `EditorAgent` 基于 Rubric + 事实核查触发，错误原文即真实归因：

| 市场 | 否决根因（总编裁决原文节选） | 归类 |
|---|---|---|
| KR | "正文内容与选题严重脱节，后半部分为无关英文内容，核心论断未经支持，事实崩塌" | 主题漂移 + 无据论断 |
| JP | "核心事实（Stripe 发布 Agent Toolkit）未被证实，安全层构成等关键数据无依据" | 事实基础崩塌 |
| JP | "正文严重偏离选题，仅首段提 AI 支付风险，后续大量无关新闻（电竞/百度/中超）" | 主题漂移 |
| US | "稿件为多篇新闻片段拼凑，逻辑断裂且含截断文本" | 拼接/截断 |
| US | "混入大量无关内容（歌手/足球运动员），核心信息跑偏，未证实论断" | 主题漂移 + 无据论断 |

**归因聚合**：
- **主题漂移（off-topic）**：3/5 —— Writer 在多信号输入下「跑题」，把无关热点写进正文。
- **事实基础崩塌（unfounded）**：2/5 —— 核心论断缺乏 `[ev]` 支撑，FactChecker 拦截。
- **拼接/截断**：1/5 —— 长输出被截断或拼凑，属免费实例推理模型输出稳定性问题。

> 关键信号：否决**全部来自 Editor 的事实/主题闸门**，没有一条是「系统崩溃」——说明**质量护栏有效**，漏出去的是"需修订"而非"错误内容"。这正是"人定义标准、AI 执行"叙事的工程兑现。

## 5. 诊断与下一步（PM 动作）

**诊断 A：主题漂移是头号问题。**
Writer 在多信号、多证据输入下容易"贪多"跑题。→ 动作：在 `Writer` prompt 加"单一论点锚定"约束 + `AngleEditor` 强化 angle 与正文的回扣校验；把"主题漂移"单独计入 `BadCase` 子类便于追踪。

**诊断 B：FPY 偏低、revise 占比高。**
本批产出内容多停留在 `revise`（需人工修订）而非 `pass`。→ 动作：评估提高 `max_review_rounds`（当前 2）是否划算；或更现实的——把"revise"内容直接进人工修订队列（`/revise` 接口已就位），把"AI 提议修订 + 人一键确认"做成标准闭环，而非追求 AI 全自动 pass。

**诊断 C：免费实例拖累耗时与稳定性。**
11.5 min/条、偶发截断，均源于 Render 免费层的冷启与串行推理。→ 动作：常驻实例或本地运行可将单条压到 1–3 min；截断问题靠推理模型输出切片策略（已实现）进一步缓解。

**对面试的价值**：这份报告没有"刷分"——它用真实输入跑出了真实短板，并给出了**可定位、可量化、可迭代**的修复路径。这比一份全绿的报告更能证明"我会用数据驱动产品决策"。

## 6. 成本结论（呼应 `METRICS_FRAMEWORK` §2.4）

- 单条真实成本 **¥0.17–0.56**，均值 **¥0.385**——与指标体系"单位质量分成本"估算区间一致。
- 对照人工：单条深度稿约 45 min 人力；AI 供给把边际成本压到"算力近常数"。
