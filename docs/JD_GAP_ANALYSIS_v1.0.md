## 二、真实缺口清单（按严重度）

### 🔴 P0 — 结构性能力缺口
**A. 工具调用设计（Tool-calling / Function-calling / MCP）**
- JD 第一优先级明确列出"工具调用设计"，是头部 AI PM 候选的高频考点。
- 现状：所有 Agent 只调用 LLM + 内部 BM25 检索，**没有任何 function-call、外部 API 调用节点、MCP**。
- 影响：面试官可能质疑"你的 Agent 只是套了壳的 Prompt 链，没有真正用工具扩展能力"。
- 补法（轻量即可，把 0→1）：让 Distributor 真实调用一个 mock 分发 API；或新增一个 WebSearch tool-calling Agent；或把 RAG 检索升级为显式 function-call 节点并在 Trace 展示入参/出参。

### 🟠 P1 — 证据级短板
**B. 评估者"人工校准"证据缺失（已建工具链，待真人分）**
- JD 强调"可评估、持续调优"；规划 W5 原要求"审核 Agent 四维评分经 50 篇人工校准 ≥80%"。
- 现状：Rubric 5 维有跑分，但**无"人工评分 vs Rubric 分"的对齐率实验**，LLM-as-judge 存在"自己评自己"的信任风险。
- **已建工具链**：`tools/calibration/compute_alignment.py`（库内 `compute_alignment_core`，被校准路由直接调用）+ 正式控制台「人工校准」页（`/console/#calibrate`）。真人从控制台逐篇/批量打分，数据落 `human_calibrations` 表并自动聚合为「真人共识分」，后端实时算 Spearman/相邻一致/偏差并生成报告+图。**试跑（AGENT_PILOT 代理标注）已跑通**：整体 Spearman ρ=0.68、相邻一致率 89%、完全一致 54%；并发现评委在"事实准确性"系统性偏严（真人 3.62 vs 评委 2.46，偏差 +1.15）——对质量闸门是正向属性。
- **待你做**：打开正式控制台 `/console/#calibrate`，以评审人身份（如 Strange）对内容逐篇或批量打分（0.5 半分 + 理由），提交即自动落库、累积、算对齐——**无需导出任何文件**。这步不依赖真实消费数据。

**C. 真实消费数据闭环**
- JD 要求"追踪点击率…持续调优"。
- 现状：消费表现（`content_events`）全为**仿真**，即便由真实信号分布校准（UI 已统一打"仿真"角标）。
- 说明：校招生无真实产品/用户，硬造点击数比标注仿真更减分；文档已把"仿真=有真实锚点的行为模型"讲成资产。**属可解释缺口，非硬伤**，面试需演讲化。

### 🟡 P2 — 包装 / 物料缺口
**D. 演示物料缺失**
- 规划 W8 要求 90 秒 demo 视频 + 架构图。仓库无 mp4，README 仅 ASCII 架构图。
- 补法：① 90 秒录屏 demo（信号→选题→成稿→审核→闭环）；② 一页架构图 PNG；③ 简历量化三件套（产出率 70.6% / FPY / 单位成本 ¥0.50 / A/B delta）。

**E. 内容侧"人工裁决理由"未结构化沉淀**
- M3 人审闸门针对 Prompt 建议；每篇内容的"人审打回/采纳理由"走 revise 机制，但**未沉淀为可复盘的裁决数据集**（规划里的"裁决表/迭代日志"）。
- 补法：把 revise 的人审意见结构化入库，形成"badcase→归因→Prompt 迭代"闭环证据链。

## 三、总体判断

- **已明显达标**：能力密度远超原规划（原规划 4 Agent + Streamlit，实际 12 Agent + 评估闭环 + 分析中心 + 闭环 A/B）。从"面试看能力密度"角度，已能逐条对仗 JD。
- **工具调用设计已补**：A（Distributor 双轨 tool-calling，含真实外部 API 调用 + Trace 可见），从 0→1 完成。
- **证据打磨**：B（评估者人工校准——工具链已建+试跑达标，待真人分替换出最终证据）、C（真实消费，可解释）。
- **包装**：D（demo 视频 / 架构图 / 简历量化）、E（裁决数据集）。
- 图片/视频生成已排除。

**一句话**：结构性达标，原"唯一硬缺口"工具调用已补；剩余是"真人校准分替换（半小时）+ 两份证据/物料打磨（消费仿真讲成资产 + demo 视频）"。
