## 3. 失败归因分布（5 条总编否决）

否决由 `EditorAgent` 基于 Rubric + 事实核查触发，下表为**裁决原文节选**（未改写）：

| 市场 | 否决根因 | 归类 |
|---|---|---|
| KR | "正文内容与选题严重脱节，后半部分为无关英文内容，核心论断未经支持，事实崩塌" | 主题漂移 + 无据论断 |
| JP | "核心事实（Stripe 发布 Agent Toolkit）未被证实，安全层构成等关键数据均无依据" | 事实基础崩塌 |
| JP | "正文严重偏离选题，仅首段提 AI 支付风险，后续大量无关新闻（电竞/百度/中超）" | 主题漂移 |
| US | "稿件为多篇新闻片段拼凑，逻辑断裂且含截断文本；核心角度完全未兑现" | 拼接/截断 |
| US | "混入大量无关内容（歌手/足球运动员），核心信息跑偏，未证实论断（宣称已发布但实为即将发布）" | 主题漂移 + 无据论断 |

**归因聚合**：

| 根因 | 占比 | 性质 |
|---|---|---|
| 主题漂移 off-topic | 3/5 | **可修复**：Prompt 约束 + 角度回扣校验 |
| 事实基础崩塌 unfounded | 2/5 | **可修复**：证据绑定强制化 |
| 拼接/截断 | 1/5 | **环境相关**：免费实例推理输出稳定性 |

> **关键信号**：5 条否决**全部来自 Editor 的事实/主题闸门**，没有一条是系统崩溃或链路异常。说明**质量护栏真实生效**——被拦下的是"跑题/无据"，而不是让错误内容漏到发布位。这是"人定义标准、AI 执行"的工程兑现，也是本项目最值得讲的一条证据。

## 4. 质量 Rubric 五维分布（12 条产出）

基于 `EditorAgent.RUBRIC_DIMS`，1–5 分，真实 LLM 评分：

| 维度 | 均值 | 解读 |
|---|---|---|
| accuracy 准确性 | **2.58** | 最弱项——免费实例下事实引用不稳，是 FPY=0 的主要拖累 |
| angle 角度 | 3.00 | 中等——切入基本成立 |
| readability 可读性 | 2.83 | 中等——结构可读但偶有不连贯 |
| local_fit 本土适配 | **3.17** | 最强项——市场档案进 Prompt 确实见效 |
| engagement 吸引力 | 2.83 | 中等——钩子/CTA 仍有空间 |

> **结论**：`local_fit > angle > readability = engagement > accuracy`。**本土化是当前唯一可稳定交付的能力，准确性是瓶颈**。这一排序直接决定了下一步优化的优先级：先修 accuracy，而不是先调风格。

## 5. 诊断与下一步（PM 动作）

**诊断 A：主题漂移是头号质量风险（3/5 否决）。**
Writer 在多信号、多证据输入下容易"贪多"。
→ 动作：`Writer` prompt 增加"单一论点锚定"硬约束；`AngleEditor` 强化 angle↔正文回扣校验；把"主题漂移"单列为 `BadCase` 子类以便追踪收敛。

**诊断 B：FPY = 0%，全部产出停留在 `revise`。**
这是本批最刺眼的数字：AI 无法一次性产出"可直接发布"的稿件。
→ 动作：**不追求 AI 全自动 pass**。把 `revise` 内容直接推入人工修订队列（`/api/contents/{id}/revise` 已就位），做成"**AI 提议修订 + 人一键确认**"的标准闭环。相比盲目提高 `max_review_rounds`（当前 2，每轮都烧钱），人机分工的成本收益比更优——这也正是产品定位从"全自动写稿"退回"供给引擎 + 人工终审"的实证依据。

**诊断 C：accuracy 是能力瓶颈（2.58，五维最低）。**
→ 动作：强化 FactChecker 的证据绑定（论断必须挂 `[ev]` 锚点，无锚点直接打回），优先于任何风格类优化。

**诊断 D：免费实例拖累耗时与稳定性。**
11.5 min/条、偶发截断，源于 Render 免费层冷启与串行推理。
→ 动作：常驻实例可压到 1–3 min/条；截断靠输出切片策略（已实现）缓解。

## 6. 成本结论（呼应 `METRICS_FRAMEWORK` §2.4）

- 真实单位有效产出成本 **¥0.50/条**（含 23.4% 废稿摊销），成功条均值 ¥0.385。
- 对照人工：单条深度稿约 45 min 人力成本，AI 供给把边际成本压到"算力近常数"。
- 按 `SCALE_DESIGN` §3 成本模型，日产 10 万条在成本路由 + 选题去重后约 **¥6,700/日**——物理上不可由人力替代，这是供给引擎的底层价值证明。
- **但**：当前 FPY=0 意味着每条仍需人工修订介入，真实全成本 = ¥0.50 + 人工修订时间。**规模化的真正瓶颈不是算力成本，是人工终审带宽**——这正是 `SCALE_DESIGN` 提出"风险分层抽样审核"的现实动因。

## 7. 环境可靠性发现（v1.1 新增，来自一次失败的扩样尝试）

试图把样本从 17 扩到 30 时，扩样批次**完整失败**，暴露了一个真实的工程约束，如实记录：

| 观察 | 现象 | 根因 |
|---|---|---|
| 3 条 `running` 任务永久消失 | 卡在 `writer` / `fact_checker` 阶段的任务在实例重启后不再存在 | 任务状态随进程内存 + 易失磁盘丢失 |
| 新触发的 3 个 job 全部 `unknown` | 触发成功、返回 job_id，但轮询时服务端已无该 job 记录 | 同上 |
| 线上历史数据从 20 条任务缩到 5 条 | DB 从 `demo_snapshot.db` 种子重建 | Render 免费实例磁盘非持久化 |

**转化为产品/工程动作**：
1. **任务状态必须持久化**，且长任务需支持**断点续跑**（当前 run 是"一次性内存态"，实例重启即全丢）——这是 `SCALE_DESIGN` 队列化改造的**真实必要性论据**，不是纸上谈兵。
2. **运行证据必须落盘沉淀**，不能只存在于易失环境。本版已将原始数据固化为 [`docs/data/RUN_EVIDENCE_v1.json`](data/RUN_EVIDENCE_v1.json)，保证报告可复现、可审计。
3. 扩样应在**常驻实例或本地带 key 环境**执行（单条 1–3 min，30 条约 1 小时），而非在会休眠重启的免费层上做长批次。

> 这次失败本身就是数据：**一个不能保存中间状态的流水线，规模化时会以同样方式失败**。把它写进报告，比假装样本量很漂亮更有价值。

## 8. 诚实标注

- **信号真实、消费仿真**：成本/质量/失败/耗时均来自真实运行；消费表现（CTR/完读）属 `METRICS_FRAMEWORK` 定义的仿真层，本报告未含，待 M2 分析中心接入仿真器后补充。
- **样本量 N=17**，小样本，分市场结论（尤其 JP n=1）仅示方向，不可作强推断。扩样失败原因见 §7。
- **3/12 产出走了降级链路**（`is_fallback=true`，某个 Agent 兜底），其信号链不完整，已在证据文件中标注 `signal_count=0`。
- **环境偏差**：Render 免费层使耗时偏高、偶发截断；结论中的"相对优劣"与"归因结构"不受影响，绝对耗时与截断率会随实例规格改善。
- **并发争用**：扩样阶段的并发触发可能加剧了单实例输出污染，§3 中"拼接/截断"1 例与此相关。
