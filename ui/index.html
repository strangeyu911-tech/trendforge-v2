AI Native 全球化内容供给引擎

把内容供给的关键流程交给 AI：信号捕捉、趋势研判、受众洞察、角度设计、证据检索、 写作、选题守卫、事实核查、总编审核、形态适配、分发策略——人负责定义标准（市场档案 / Prompt / 评估 Rubric）， AI 在真实消费反馈中持续进化。

SENSE 感知信号捕捉 → 趋势研判 → 受众洞察 → 角度设计
PRODUCE 生产证据检索 → 写作 → 选题守卫 → 事实核查 → 总编审核
AMPLIFY 放大形态适配（短视频/卡片/快讯/评论）→ 分发策略
EVALUATE 评估与进化消费数据 → 评估报告 → 迭代建议 → 人工校准

3 分钟看懂这个 Demo（按顺序点）

控制台有 9 个模块，第一次打开容易不知道从哪看起。这条路径覆盖了最能说明问题的五站。

① 跑供给 选一个市场点「开始供给」，看 11 个 Agent 依次执行。 重点：任务在服务端运行，切页面或刷新都不会中断。 ② 打开一条内容 母稿 + 多形态派生 + 分发计划 + 可点击溯源的真实信号 + 每一步的执行 Trace。 重点：非中文内容默认「原文 + 中文对照」。 ③ 分析中心 九张图全部由后端手写 SQL 实时算出。 重点：每张图下方可展开驱动它的真实 SQL；仿真数据的图都带「仿真」角标。 ④ 人工校准 五维半分制打分 + 逐维理由，与 EditorAgent 的评委分做 Spearman 对齐。 重点：机器裁决和真人打分的差值，正是这个模块存在的理由。 ⑤ 系统进化 AI 提议 → 你拍板采纳（无需重启即刻生效）→ 效果回收对比 → 随时回滚。 重点：A/B 不让机器替你判胜负，看完由人二选一。

14 个 Agent：主管线 11 + 治理/分析 3

「跑供给」页的进度条就是下面第一条流水线（含 TopicGuard 选题守卫）；另外 3 个不在主管线里， 分别负责知识库治理、反馈分析和中文对照。控制台里的中文名与此表完全一致。
